# Visual QA checklist

Use [webapp-testing](../../webapp-testing/SKILL.md) for Playwright throughout implementation, [web-design-guidelines](../../web-design-guidelines/SKILL.md) for interface/accessibility review and applicable [vercel-react-best-practices](../../vercel-react-best-practices/SKILL.md) for React performance. This is Vite with React, not an assumption of Next.js architecture.

## Required evidence for every redesigned page

- Desktop viewport: **1440×1000**.
- Mobile viewport: **390×844**.
- Inspect the running homepage and target before changes. Capture early, intermediate and final target-page states.
- Wait for the rendered page and assets before identifying controls. Scroll the full page in both directions, allowing viewport-driven content to appear. Capture full-page and viewport screenshots; full-page images alone do not test fixed layers or transitional overlaps.
- Exercise complete animation cycles, including entering, receiving/updating, decisions, human approval, exceptions, completion, exit, replay and reset where applicable.
- Test click/touch interactions and keyboard controls: Tab order, focus visibility, Enter/Space, Escape, modal focus and return focus. Test navigation and footer destinations plus redirect aliases.
- Test reduced motion at load and when changed during use; content and controls must remain usable without continuous animation.
- Inspect floating panels at their maximum travel bounds and intermediate states. Check heading/button/body/panel collisions and no more than two simultaneous floating panels on small mobile screens.
- Open mobile navigation while the centrepiece runs. Verify layering, pointer access, focus containment, background scroll handling and recovery after closing.
- Check horizontal and vertical overflow, clipped required information, sticky/fixed elements and small-screen text wrapping. Simplify the composition rather than merely concealing overflow.
- Check missing images, model/font assets, network failures, console errors and page exceptions. Exercise animation/WebGL fallbacks and confirm usable HTML remains.
- Inspect real form validation and failure feedback; do not submit an external enquiry unless authorized. Use a safe adapter/test fixture for delivery-state testing.

## Visual inspection and correction

Open and visually inspect the saved desktop and mobile screenshots. Review typography, actual text contrast, controlled headings, warm-white important text, palette provenance, surface hierarchy, lighting, negative space and the meaningful centrepiece. Compare with the approved homepage without copying its robot.

Correct visible defects and repeat the relevant cycle and screenshot inspection. HTTP 200, lint and build success are not visual approval. Report screenshot paths, viewport sizes, inspected states and any unresolved defects; never claim screenshots were inspected merely because they were saved.

## Protection and completion

Compare protected source hashes/diffs against the before-change baseline, preserving pre-existing user edits. Confirm the homepage and `/command-centre`, `/retailer` and `/discovery` remain unchanged. Shared shell, token or routing changes can affect protected areas even if their page files did not change; inspect those routes if shared dependencies were touched.

Run the bundled verifier: lint → typecheck → production build, stopping at the first failure. It prints every current public route requiring visual inspection, including redirect aliases and a sample unmatched route. It does not start a server, choose a port, kill processes, change dependencies or edit production source. Build output is generated by the existing project build command. Review route inventory against current routing when new pages are added.

Final evidence: changed files, behaviour demonstrated, desktop/mobile visual inspection, interaction and reduced-motion results, asset/console findings, lint/typecheck/build results, protected-area comparison and remaining issues. If a required check is blocked, name it and do not declare completion of the website work.
