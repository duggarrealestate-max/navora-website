# Anti-SaaS rules

Reject these patterns as the basis of a NAVORA public redesign:

- Hero followed by card grids.
- Repeated three-column sections.
- Oversized gradient headings.
- Random glowing orbs.
- Static decorative dashboards.
- Identical glass cards.
- Meaningless particles.
- Fake clients, results or testimonials.
- Empty AI jargon.
- Designs made futuristic only by adding grids or glow.
- Copied component-library layouts.
- Purple-gradient AI aesthetics.

A page is not redesigned merely because a signal strip, glow, grid or floating card was added. Preserve the approved homepage even where existing elements resemble a rejected new-design pattern; these rules are not authorization to rewrite it.

## Review the concept before building

Explain what useful work the centrepiece demonstrates, which visitor action changes it and how the outcome becomes visible. If the explanation still fits any generic AI landing page, revise it around the page's actual content.

Use abstract functional technology on subpages: orchestration maps, signal paths, changing interface windows, approval gates, processing states and connected systems. Let layout follow the work being demonstrated instead of chopping content into uniform cards. Keep headings readable, important text solid warm white, body text legible and surfaces differentiated by purpose.

Preserve negative space, restrained directional lighting and the verified black/graphite foundation. Do not introduce new blue, violet, purple, yellow or gold. Never guess colours from memory or copy a legacy component's accent defaults. An existing accent is not a license for a new purple-gradient identity.

Critique the actual screenshots using [frontend-design](../../frontend-design/SKILL.md), applying NAVORA-specific requirements over generic aesthetic suggestions. Remove elements whose only function is to look futuristic; retain motion that clarifies information, choices, actions and outcomes.
